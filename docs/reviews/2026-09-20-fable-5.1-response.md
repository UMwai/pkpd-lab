## Response

I read the snapshot as static text only. Nothing below is based on executing tests, the CLI, or the app.

## Overall assessment

The engine is small, readable, and its documentation is unusually honest. The event handling, mass ledger, and validation table match the code closely. I found no confirmed numerical defect by inspection. I did find one confirmed schema-level units inconsistency, several documentation gaps, and a set of untested paths that the validation record should list explicitly.

## Confirmed findings

**1. Rate-constant field names carry an hours suffix but hold 1/h values.** `absorption_rate_h`, `effect_equilibration_h`, and `turnover_rate_h` are defined at `src/pkpd_lab/models.py:24`, `:52`, `:53`. They are used as 1/h in `src/pkpd_lab/simulation.py:82`, `:92`, `:99`. The README contract says rate constants are 1/h, and AGENTS.md line 4 demands explicit units. The UI labels are correct, but the JSON schema and Python API are misleading. This is a units-labeling defect. Record it in MODELS.md and README now, and plan a rename in a schema version 2 rather than living with it.

**2. Reproducibility receipt is thinner than described.** README lines 80 to 81 say the receipt records "dependency versions". The CLI records four packages at `src/pkpd_lab/cli.py:26`. It omits pandas, which writes the CSV, and omits the Python version, platform, and git commit. The SHA-256 at `cli.py:22` to `:25` hashes pydantic's canonical re-serialization, not the bytes of the input file. The README should say so, because a user hashing their own file will get a different digest.

**3. Files the documentation depends on are not in the snapshot.** I could not see `pyproject.toml`, `uv.lock`, `src/pkpd_lab/__init__.py`, `LICENSE`, `docs/workbench.png`, or the three `examples/*.json` files referenced at README lines 75 to 77 and `.github/workflows/ci.yml:23`. The public API imported by `app.py:10` and the tests therefore cannot be confirmed from this snapshot. I am not asserting they are missing, only that the review cannot vouch for them.

**4. Observation-time rule is incomplete in the docs.** MODELS.md line 98 says times must be finite, unique, and increasing. The code at `simulation.py:54` also rejects times outside the closed interval from zero to the horizon. Add that.

**5. Untested UI paths.** JSON import (`app.py:45`, `:107`) and the editable dose ledger (`app.py:118` to `:127`) have no automated coverage. Streamlit AppTest cannot drive file uploads or data editors, so this is structural, not negligence. VALIDATION.md line 21 lists the workbench as checked without this caveat.

**6. Validation table implies broader PD coverage than the tests provide.** Indirect response is verified only with the plasma driver (`tests/test_simulation.py:187`). The effect-site driver for indirect models, Hill coefficients other than one, the linear PD model with nonzero drug, and Michaelis-Menten combined with linear clearance or with peripheral compartments have no reference-solution test. Combined nonlinear cases are covered only by mass conservation (`tests/test_simulation.py:143` to `:157`), which cannot catch a wrong but conservative rate law.

**7. Solver failures outside the main try block reach the user as tracebacks.** The comparison tab at `app.py:284` and the population button at `app.py:313` call the engine without catching RuntimeError. The trajectory path at `app.py:157` does. This is consistent with "never hide solver failures" but is inconsistent presentation.

## Things I checked and found correct

- Right-continuous bolus observations. Events at a boundary are applied before the state is written at `simulation.py:105` to `:110`, and the previous segment's endpoint is overwritten. Tested at `tests/test_simulation.py:68` and `:123`.
- Mass ledger identity at `simulation.py:145` matches MODELS.md line 47, including pending lag and the one-minus-F loss.
- Overlapping infusion rates sum at `simulation.py:114` to `:118`. Partial delivery at the horizon is accounted at `:138`.
- Lognormal variance in `experiments.py:68` matches the documented form, and typical values are medians as stated.
- The integrated Michaelis-Menten reference at `tests/test_simulation.py:139` is algebraically correct for the chosen parameters.
- The matrix exponential reference at `tests/test_simulation.py:54` to `:59` assembles the mammillary system correctly.
- The occupancy function at `simulation.py:16` returns zero at zero concentration through the log-space path.

## Hypotheses and untested concerns

- **Uniform absolute tolerance across mixed units.** `atol=1e-10` at `simulation.py:127` applies equally to milligram amounts, AUC in mg·h/L, and a response variable that may sit at ten thousand units. This is harmless at the tested scales. It is worth documenting and worth a per-component tolerance in a later version.
- **Non-smooth right-hand side.** Concentration is clipped at zero for elimination at `simulation.py:81` but not for intercompartmental exchange at `:87`. LSODA's finite-difference Jacobian could be perturbed near zero. I have no evidence this bites.
- **Accumulated drift at scale.** The mass check threshold is relative to total administered drug at `simulation.py:147`. Ten thousand oral doses create roughly twenty thousand segments. Whether drift stays below one part per million there is untested.
- **Quantile Monte Carlo error.** Fifth and 95th percentiles from fifty subjects have large sampling error. Neither the docs nor the UI caption at `app.py:343` mentions this.
- **Fragile exact-equality assertion.** `tests/test_cli.py:24` compares a float parsed from CSV with the JSON value by exact equality. Current pandas round-trips floats, so it should pass. It could break on a pandas upgrade.
- **Reference link.** `docs/REFERENCES.md:10` cites a 2026 mrgsolve post for three-compartment PKMODEL support. I could not verify that page or that claim.

## Does the documentation overclaim?

Mostly no. The repeated statements that this is not a validated drug model, that bands are not confidence intervals, and that comparisons do not rank models are appropriate and consistent with the code. Two wording problems remain. README line 41 and MODELS.md line 120 use "validated" for scenarios that are schema-validated by pydantic. In a project that carefully separates numerical verification from empirical validation, that word choice blurs the line. Every feature in the README table is present in the code I could see. No labeled feature is absent, subject to the missing-file caveat above.

## Suggested documentation edits

1. README line 41 and MODELS.md line 120: replace "validated" with "schema-validated".
2. README lines 87 to 88 and MODELS.md section one: add a sentence stating that fields ending in `_h` for absorption, equilibration, and turnover hold rate constants in 1/h, and that a schema version 2 will rename them.
3. README lines 80 to 83: state which package versions are recorded, that Python and platform are not, and that the hash is of the canonical re-serialized scenario.
4. MODELS.md line 98: add the closed-interval constraint on observation times.
5. VALIDATION.md: add a "Not covered" section listing the items in finding six, plus the UI import and ledger paths, and the untested large-schedule regime.
6. MODELS.md lines 113 to 118: note the quantile method and that band edges carry Monte Carlo error that shrinks with subject count.
7. MODELS.md line 95: note that the absolute tolerance is shared across state components with different units.
8. `app.py:200`: change the x-axis title to "Time since simulation start (h)".
9. REFERENCES.md item one: verify or remove the three-compartment PKMODEL citation.

## Material defect to record rather than smooth over

The units suffix problem in finding one is the only defect I would call material. It cannot be fixed with prose alone, because renaming fields breaks every saved scenario JSON and the CLI hash. The honest path is a dated note in MODELS.md acknowledging the misnomer, a deprecation plan tied to schema version 2 with a migration, and no silent aliasing in version 1.

## Prioritized roadmap

1. **Close the verification gaps.** Add reference tests for indirect response with the effect-site driver, Hill not equal to one, the linear model with drug, and Michaelis-Menten in a two-compartment system against a high-accuracy reference solve. Add a stress test with several thousand doses that checks the mass residual and runtime.
2. **Harden the receipt.** Record Python version, platform, pandas and streamlit versions, and the git commit when available. Document hash semantics.
3. **Schema version 2.** Rename rate-constant fields with a `_per_h` suffix, add a migration for version 1 files, and keep the version 1 loader.
4. **Between-grid extrema.** Refine Cmax and Tmax by local search inside the segment containing the sampled peak, using the solver's dense output. Keep the sampled values as well.
5. **Event-time robustness.** Keys in the events dictionary at `simulation.py:57` rely on exact float equality between dose time plus lag and the boundary set. This works today because the same expression produces both. Snapping times to a shared representation would remove a latent fragility.
6. **Tolerance design.** Move to per-component absolute tolerances scaled by dose and baseline.
7. **Then** proceed to the existing roadmap item one, admitting a single well-documented published model with an evidence record.

## Recap

No confirmed numerical error was found by reading. One confirmed units-labeling defect in the schema field names should be documented now and fixed in a versioned schema change. The validation record is honest but should list what it does not cover. The receipt and hash semantics need a clearer description. Several supporting files were outside the snapshot and remain unverified.
